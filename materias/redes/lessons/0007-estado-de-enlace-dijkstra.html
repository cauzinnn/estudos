1. A Filosofia Link State (LS): Mapa Global Unificado

Enquanto o Vetor de Distância opera por fofoca ("diga aos vizinhos o que sabe do mundo"), os protocolos de Estado do Enlace operam pela lógica inversa:

"Diga a todo o mundo exatamente o que você sabe sobre os seus vizinhos imediatos."

Cada roteador descobre seus enlaces diretos e seus custos, empacota essas informações em um LSA (Link State Advertisement) e o inunda por toda a área.

Todos os nós recebem esses LSAs e constroem em memória uma Link State Database (LSDB) rigorosamente idêntica: o grafo geométrico completo da topologia. Com a LSDB em mãos, cada roteador executa localmente o Algoritmo de Dijkstra para gerar sua própria árvore de caminhos mínimos, imune a loops de contagem ao infinito!

2. Os Três Conjuntos do Algoritmo de Dijkstra (SPF)

Para derivar a árvore de menor caminho da raiz $S$ para todos os nós $V$, o algoritmo manipula três conjuntos:

  • $C$ (Confirmados): Nós para os quais o caminho ótimo definitivo já foi comprovado. Inicia com $C = \{S\}$.
  • $R$ (Restantes): Nós da rede ainda não confirmados ($R = V - C$).
  • $O$ (Tentativos): Lista de caminhos candidatos ordenados por custo acumulado crescente.
📌 Mecânica do Passo a Passo de Mesa
  1. Remove de $O$ o caminho $P$ de menor custo acumulado. Seja $U$ o nó folha de $P$.
  2. Teste de Otimização: Se $U \in C$, o caminho $P$ é descartado (pois já encontramos antes um caminho melhor ou igual para $U$).
  3. Se $U \notin C$, então $P$ é o caminho mínimo definitivo para $U$! Move-se $U$ de $R$ para $C$.
  4. Concatena-se $P$ com todos os enlaces que saem de $U$, inserindo os novos caminhos na lista ordenada $O$.

4. Derivação da Tabela de Encaminhamento (FIB)

O algoritmo de Dijkstra produz a árvore geradora de caminhos mais curtos (Shortest Path Tree).

Para construir a tabela de repasse (FIB), o roteador $A$ precisa registrar, para cada destino, qual é o vizinho direto imediato (Próximo Salto / Next Hop) na interface de saída:

  • Para o destino $B$: caminho $A-B$ $\to$ Next Hop = B.
  • Para o destino $D$: caminho $A-D$ $\to$ Next Hop = D.
  • Para o destino $E$: caminho $A-B-E$ $\to$ Next Hop = B.
  • Para o destino $C$: caminho $A-B-C$ $\to$ Next Hop = B.
  • Para o destino $F$: caminho $A-B-E-F$ $\to$ Next Hop = B.

5. Complexidade Computacional: Dijkstra vs. Bellman-Ford

A complexidade computacional do algoritmo de Dijkstra depende da estrutura de dados usada para gerenciar a lista de caminhos tentativos $O$:

  • Implementação Simples (Busca Linear): $O(V^2)$, onde $V$ é o número de roteadores.
  • Implementação com Heap Binário (Min-Heap / Fila de Prioridade): $O((V + E) \log V)$ ou $O(M \log M)$, onde $E$ (ou $M$) é o número de enlaces.

Em redes esparsas comuns de telecomunicações, o Dijkstra converge muito mais rapidamente em CPU que o Bellman-Ford distribuído ($O(N \cdot M^2)$ rodadas com trocas contínuas).
