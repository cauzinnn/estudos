Cabeçalho IPv4, Fragmentação, Roteamento pela Fonte e ICMP

Estrutura de 20 a 60 bytes, aritmética de Fragment Offset em blocos de 8 octetos, a armadilha do Slow Path em opções, túneis IP-em-IP e ICMP Redirect.

1. Estrutura Básica do Cabeçalho e o Campo IHL

O cabeçalho IPv4 varia entre 20 e 60 bytes. Como o campo IHL (Internet Header Length) possui apenas 4 bits (valores de 0 a 15), ele codifica o comprimento em palavras de 32 bits (4 bytes):

  • Sem opções (padrão): $IHL = 5$ ($5 \times 4 = 20$ bytes).
  • Com opções máximas: $IHL = 15$ ($15 \times 4 = 60$ bytes, restando $40$ bytes para opções).
  • Time to Live (TTL): Decrementado por cada roteador; se chegar a zero, o pacote é destruído e gera ICMP Time Exceeded (Tipo 11).

2. Fragmentação: MTU, Flags e Fragment Offset

Quando um datagrama excede a MTU (Maximum Transmission Unit) de um enlace, ele precisa ser fragmentado (a menos que a flag DF - Don't Fragment esteja ativada):

  • O cabeçalho IP (20 bytes) é replicado em cada fragmento.
  • A flag MF (More Fragments) vale 1 em todos os fragmentos, exceto no último (onde vale 0).
  • O campo Fragment Offset possui 13 bits e indica a posição dos dados do fragmento em relação ao payload original, medido obrigatoriamente em blocos de 8 octetos (64 bits):

$$\text{Fragment Offset} = \frac{\text{Bytes de dados acumulados anteriores}}{8}$$

3. Comutação no Hardware: Fast Path vs. Slow Path

Roteadores modernos encaminham a imensa maioria dos pacotes através do Fast Path: chips dedicados (ASICs / NPUs) processam o cabeçalho padrão de 20 bytes em microssegundos no plano de dados sem intervenção de software.

Entretanto, quando um datagrama IPv4 possui o campo de Opções preenchido ($IHL > 5$), o hardware não consegue processá-lo na linha de velocidade do enlace. O pacote é forçado para o Slow Path (plano de controle), sendo enviado à CPU principal do roteador.

Isso aumenta drasticamente a latência e abre brechas para ataques de negação de serviço (DoS) por sobrecarga do processador do roteador.

4. Loose / Strict Source Routing vs. Encapsulamento IP-em-IP

Para forçar que um datagrama atravesse uma sequência pré-determinada de roteadores, existem duas abordagens fundamentais:

  • Roteamento pela Fonte (Opções IP):
    • Loose Source Routing (LSR): O pacote deve passar pelos roteadores listados, mas pode passar por nós intermediários livres entre eles.
    • Strict Source Routing (SSR): O próximo roteador listado deve ser vizinho físico direto; se não for, o pacote é descartado.
  • Encapsulamento IP dentro de IP (Túnel RFC 2003): Adiciona um cabeçalho IP externo para cada nó intermediário forçado. Não utiliza o campo de opções, trafegando pelo Fast Path nos nós internos ao túnel!

Diferença crucial de capacidade: Como o cabeçalho IP possui no máximo 60 bytes, o espaço reservado para opções é de 40 bytes ($60 - 20$). Subtraindo 3 bytes de cabeçalho da opção de rota, restam 37 bytes. Como cada IP consome 4 bytes, cabem no máximo $\lfloor 37 / 4 \rfloor = 9$ endereços intermediários forçados!

5. Mensagens de Redirecionamento ICMP (ICMP Redirect)

Uma mensagem ICMP Redirect (Tipo 5) é gerada por um roteador $R_A$ para informar uma estação de origem que ela escolheu um próximo salto subótimo.

Ela é disparada sob uma condição operacional estrita:

  • O pacote entra pela interface física $X$ de $R_A$.
  • A tabela de encaminhamento de $R_A$ determina que o melhor próximo salto para o destino está na mesma interface física $X$ (interface de entrada igual à interface de saída!).

$R_A$ encaminha o pacote para o outro roteador $R_B$ e envia o ICMP Redirect para a estação de origem, informando-a para enviar tráfegos futuros para aquele destino diretamente a $R_B$, eliminando o salto duplicado na rede local.
